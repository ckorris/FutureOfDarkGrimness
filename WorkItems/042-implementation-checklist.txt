Notes on what differs from the original sketch:
  - All enums use E-prefix project convention (EStatKind, EActionType,
    ERollKind, ELifetime, EHookID).
  - Condition.StatGreaterOrEqualTo takes both EStatKind and int (not just int)
    so the comparison knows which stat to read.
  - Effect.StatModifier takes ELifetime (without it, persistent stat tweaks
    couldn't declare their duration). Effect.GrantToken takes Count and
    TokenClearTrigger (without them, every grant would lack count and clear
    policy).
  - DiceExpression keeps both generic DX(int) and specific D3/D6/CoinFlip;
    overlap between e.g. DX(3) and D3 is a known wart (different types,
    same semantics). Resolve when a real test forces the issue.
  - Aura kept separate from AddRule (Aura propagates unit-wide; AddRule grants
    to bearer only).
  - Heal is the only Effect with a DiceExpression amount; everything else
    uses plain int/float for fixed authored values.
  - IEntityRef marker interface dropped — token operations are split into
    Unit/Model variants for compile-time safety instead.

IMPLEMENTATION PROGRESS (2026-06-06) — suite 215 green / 8 red (231 / 8 after merging
master's +16 LoS/terrain tests). ALL passively-dispatchable rules now green:

  * SWITCHES -> POLYMORPHISM. The 06-03 EvaluateCondition/MapEffect switches in
    RuleEvaluator are GONE. Logic now lives on the records: Condition.Evaluate(RuleInvocation)
    and Effect.Apply(RuleInvocation, ops). RuleEvaluator is just the loop now.
    Capability requirement carried by a GENERIC INTERMEDIATE: CapabilityCondition<TCap> /
    CapabilityEffect<TCap> (Rules/Definitions) where the type arg IS the required capability
    — one binding in the leaf's base clause gives both the typed EvaluateCore/ApplyCore body
    and the reflectable RequiredCapabilities (= [typeof(TCap)]). Capability-free primitives
    override the untyped method directly; composites (And/Not) union/passthrough children.
    New marker ICapability (Foundation) tags capability interfaces. WHY (not the switch):
    rules will be authored as JSON via a tool that links this library, never by hand — the
    compiler never sees a tool-composed rule, so compile-time exhaustiveness was never the
    guard; per-record methods + a runtime validator is the honest shape.
  * RULE VALIDATOR (the authored-rule safety net). Rules/Dispatch/RuleValidator.cs:
    Validate(SpecialRuleDefinition) -> RuleViolation[] checks each HookEntry's condition+effect
    RequiredCapabilities against the capabilities its hook's context provides. Empty req =
    always valid; unknown hook = skipped. Shared by engine-at-load AND the future tool
    (validate-before-save; also drives the tool's dropdowns so a bad pairing is unconstructible).
    HookContextCatalog.cs supplies hook->provided-capabilities, built BY REFLECTION (read each
    IHookContext's constant Hook off an uninitialized instance) — no hand-maintained table.
    4 tests in Tests/RuleValidatorTests.cs.
  * RULEINVOCATION (bearer + args threading). Evaluate/Apply now take
    RuleInvocation(IHookContext Hook, IUnit Bearer, IReadOnlyList<RuleArgument> Arguments)
    instead of the bare context (bearer/args can't live on the hook ctx — same event is
    evaluated for several units/seats). Built per-rule in RuleEvaluator's loop. ValueSource
    gained Resolve(arguments) (Literal -> value; Arg(i) -> arguments[i]). This unblocked the
    arg-bearing effects (Deadly/Tough/Blast/Impact/Fear), bearer-targeted GrantToken
    (Caster/Piercing Frenzy/Limited; new TokenType.RuleGrant), Aura (one rule-grant token on
    the bearer; per-model expansion still deferred), and TokenPresent (reads Bearer.Tokens).
    Public RuleEvaluator.Evaluate(unit,seat,context) + harness Evaluate(...) signatures unchanged.
  * CAPABILITIES/CONTEXTS added: IHasActionType (in Definitions, not Foundation — it refs
    EActionType, a Definitions type, and Foundation stays dependency-free), IHasAttackerMoved
    (Foundation). HitRollCompleteContext now also : IHasDistance (Relentless's And);
    HitRollModifierContext : IHasAttackerMoved (Indirect); MoveActionDeclaredContext :
    IHasActionType (Fast/Slow/Immobile).
  * ALL passive rules migrated to Evaluate (seats verified by going green; defensive rules —
    Stealth, Melee Shrouding, Regeneration, Counter, Aircraft — carry ERuleSeat.Subject).
  * 8 RED REMAIN, both groups out of scope for PASSIVE dispatch:
      - 7 activated abilities (Mend x2, Advanced Sight, Unstoppable Mark place, Vanguard,
        Martial Prowess, Strafing) — still on GatherOffers/ResolveAbility bus stub. => PHASE 7c
        (next milestone; clears 6 of the 8).
      - 1 token-clear (Unstoppable Mark owner-destroyed) — needs a TokenClearService walking
        containers on OnUnitDestroyed to remove OwnerDestroyed tokens. Not a queue concern.
  * BUS now backs only: the no-rules smoke test (harness.Fire) + the 7 activated-ability tests
    (OfferAbilities/Accept). Retires at 7c.
  * STILL DEFERRED (unchanged): C#-catalog/JSON loader (defs still inline in tests), behavior-
    level execution of queued ops (PHASE 8), per-model aura expansion, Hero/Transport.

IMPLEMENTATION PROGRESS (2026-06-03, post-break session) — suite 179 green / 40 red:

  * 7-spine LANDED, but NOT as a bus. Decided the "bus" was dead weight: the caller
    always knows the units and roles involved and needs the operation queue back
    synchronously (a query, not a broadcast). So dispatch is a stateless
    Rules/Dispatch/RuleEvaluator.cs with:
        Evaluate(IUnit unit, ERuleSeat seat, IHookContext context) -> IReadOnlyList<RuleOperation>
    The caller (stage / test) addresses each involved unit directly, once per seat
    (e.g. attacker as Actor, defender as Subject), and applies the returned ops.
  * SEAT MODEL: ERuleSeat { Actor, Subject } (Rules/Foundation). It's a field on
    HookEntry, defaulting to Actor; only defensive entries state Subject. An entry
    fires only when entry.Seat == the seat the caller is evaluating, so a wrong-seat
    rule simply can't match (Stealth on a shooter does nothing — there's a test).
  * CONDITIONS read context fields via tiny CAPABILITY INTERFACES (Rules/Dispatch/
    IHasDistance, IHasUnmodifiedHitRolls) so the evaluator never downcasts to a
    concrete context. EvaluateCondition / MapEffect are pattern-match switches over
    the closed Condition/Effect sum types (default: throw — gaps surface loudly).
    Add a capability interface per new field on demand.
  * DICE RESULTS = IDiceResults (the engine's per-face histogram), NOT int lists.
    Roll-bearing contexts (HitRollComplete, SaveRollComplete) and IHasUnmodifiedHitRolls
    carry IDiceResults; "natural 6" is results.At(6). Dice-DERIVED operation counts
    are float (InsertExtraHits / InsertExtraWounds / InvokeHeal) because they are
    fractional under the ProbabilisticDiceRoller (n dice -> n/6 sixes). Authored
    counts (multipliers, dice-to-roll, fixed hit counts) stay int. Tests build
    histograms via Tests/RulesHarness/TestDice.Faces(...). THIS IS A PROJECT-WIDE
    INVARIANT: never int-lock a value that derives from a die roll.
  * DONE so far (via Evaluate): Stealth (Subject, DistanceGreaterThan -> ApplyRollModifier)
    and Furious (Actor, UnmodifiedRollEquals/At(6) -> InsertExtraHits). Conditions
    implemented: DistanceGreaterThan, UnmodifiedRollEquals. Effects: RollModifier,
    AddExtraHit.
  * THE BUS IS DYING, NOT DEAD. RuleHookBus + harness.Fire still back the 34 not-yet-
    migrated passive tests; GatherOffers/ResolveAbility (7 activated-ability tests:
    1 OfferAbilities + 6 Accept) have no evaluator home until 7c. MIGRATION RULE:
    flip each test Fire->Evaluate WHEN its rule is implemented (the green verifies the
    seat). Do NOT bulk-migrate unimplemented rules (sets seats blind, just trades
    clean-red for throw-red). Delete Dispatch/Fire when the last passive rule migrates;
    delete the rest of the bus at 7c.
  * NOT DONE: a canonical rule catalog (C# or JSON). Stealth/Furious definitions are
    still inline in tests. Deliberately deferred — JSON loader will own this later;
    a notepad file holds the catalog meanwhile. Don't build a C# CoreRules catalog now.

[ ] 7-spine — Dispatcher (RuleHookBus.Dispatch), the piece everything needs
       Implement: walk the relevant units' ResolvedRules, match HookEntry by
       EHookID against the firing context, evaluate Condition, translate matching
       Effects -> RuleOperation(s), resolving ValueSource.Arg(i) against the
       firing rule's Arguments.
       CRUX DECISION — SETTLED 2026-05-29 (see arch doc "Phase 7 design notes"):
       A rule is an egocentric statement keyed on a perspective-anchored "when"
       (perspective FUSED into the trigger, not a separable side-tag — so a
       wrong-seat rule simply can't match). Dispatch evaluates rules carried ONLY
       by the units the firing event NAMES as participants (target for
       defender-side whens, attacker for attacker-side whens — the old
       GetDefender/GetAttackerSpecialRules scoping, as data). NO board scan.
       Relational rules (Fear, Melee Shrouding) read another unit's rules only
       when that unit is a participant in the same event, via a TargetHasRule-style
       condition. Conditions stay SEPARATE from whens (whens = moment x seat;
       quantitative/comparative tests = conditions) so whens stay finite and
       conditions can stack. Per-event flow: when fires -> evaluate conditions
       (maybe none) -> add effect to queue.

unimplemented. This second pass closes that gap:

       multiplied, model actually healed, token actually granted, etc.).

APPENDIX B — Whens per special rule (brainstorm 2026-05-29)
----------------------------------------------------------

Source: GF Beginner's Guide "Special Rules Reference" (pp.13-15) — matches the
project's v3.5.1 corpus (has Takedown/Artillery/Limited). All 32 rules except AP.

A "when" is the perspective-FUSED trigger (moment x seat) decided in the Phase 7
design session: "when I shoot" and "when an enemy shoots me" are DIFFERENT whens
over the same engine event. Under the hood a when maps to (EHookID x seat); the
seat is resolved by which participant carries the rule, so authoring a wrong seat
is impossible. Conditions/effects are shown in [..] only to justify the when — they
are NOT part of it (they layer on top and stack). High reuse below is the point:
basic whens cover many rules.

CANONICAL WHEN VOCABULARY (deduped, grouped by resolution phase)
  Round/lifecycle
    [W1] when a round starts (self)
    [W2] when this model is created (self)
  Deployment
    [W3] when this unit deploys (self)
    [W4] when objective control is checked for this unit (self)
  Action / movement (actor seat)
    [W5] when this unit declares an action (self=actor)
    [W6] when this unit moves (self=mover)
    [W7] when this unit charges (self=charger)
  Charge defense (defender seat)
    [W8] when this unit is charged (self=charged)
  Shooting — attacker seat
    [W9]  when this unit selects a shooting target (self=attacker)
    [W10] when this unit rolls to hit (self=attacker)  -- shooting OR melee; the
          shoot/melee split is a CONDITION (combatKind), NOT a separate when
    [W11] when this unit's hits are totaled (self=attacker)
  Shooting — defender seat
    [W12] when an enemy rolls to hit this unit, shooting (self=target)
  Melee
    [W13] -- MERGED INTO W10. Melee hit rolls reuse the hit-roll when via the combatKind
          flag (arch doc hook-surface: "shoot hooks reused ... for everything else").
          Only charge-contact / counter / melee-resolution / post-melee are melee-only moments.
    [W14] when melee is resolved (self=combatant)
  Saves / wounds
    [W15] when the target saves against this unit's attack (self=attacker)
    [W16] when this unit's attack wounds the target (self=attacker)
    [W17] when this unit takes a wound (self=defender)
    [W18] when wounds are assigned to this unit (self=defender)
    [W19] when the target would ignore a wound from this unit's attack (self=attacker)
  Morale
    [W20] when this unit fails a morale test (self)
  Casting
    [W21] when this unit casts a spell (self=caster)
    [W22] when a friendly caster casts within 18" of this unit (self=assisting)  *** TRIPWIRE
  Weapon availability
    [W23] when this unit attacks with this weapon (self=attacker)

OBSERVATIONS
  - TWO distinct mechanisms, don't confuse them: (a) a rule may list MULTIPLE whens
    (a SpecialRuleDefinition is a LIST of HookEntries) for genuinely DIFFERENT moments
    -- Aircraft 4, Bane 2, Tough 2; (b) a single moment that occurs in BOTH shooting
    and melee (hit/save/wound rolls) is ONE when with combatKind as a CONDITION, not
    two whens. Surge is case (b); splitting it into shoot+melee whens was over-cutting.
  - W6 ("when this unit moves") alone carries Fast/Slow/Flying/Strider/Aircraft —
    confirms whens should stay basic and let conditions/effects differentiate.
  - W10 ("rolls to hit") is the busiest by far: Artillery/Indirect/Relentless/Surge/
    Reliable/Rending/Unstoppable + melee Furious/Thrust. Shooting-only ones add a
    [shooting] condition, melee-only ones add [melee]; pure weapon rules (Surge/
    Reliable/Rending/Unstoppable) add neither and fire in both. All differ only by
    condition/effect.
  - W19 is a pure SUPPRESSION when shared by Bane/Rending/Unstoppable (all "ignore
    Regeneration") — feeds the 7b first-pass suppression decision.
  - ORDERING flags (Blast "after other rules", Deadly/Takedown "resolved first") are
    the concrete cases behind the 7b feedback/precedence open question.
  - W22 (Caster assist within 18") is the ONE proximity-to-non-participant rule in
    the corpus — the aura tripwire. If we implement assist, the pull model returns
    for it alone; otherwise defer.
