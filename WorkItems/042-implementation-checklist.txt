Notes on what differs from the original sketch (see architecture doc's
"Phase 1 & 2 implementation notes" for full rationale):
  - TokenType IsSingleton lives on the type itself (instance property +
    custom Equals + throw on mismatch), not in a centralized registry.

    deferred to the effect-dispatch layer (Phase 7d).

    OnTokenRemoved), each fired at most once per mutation.
  - Token.ClearTrigger is required (non-nullable); ManualOnly for permanent.

Notes on what differs from the original sketch:
  - All enums use E-prefix project convention (EStatKind, EActionType,
    ERollKind, ELifetime, EHookID).
  - Condition.StatGreaterOrEqualTo takes both EStatKind and int (not just int)
    so the comparison knows which stat to read.
  - Effect.StatModifier takes ELifetime (without it, persistent stat tweaks
    couldn't declare their duration). Effect.GrantToken takes Count and
    TokenClearTrigger (without them, every grant would lack count and clear
    policy).
  - DiceExpression keeps both generic DX(int) and specific D3/D6/CoinFlip;
    overlap between e.g. DX(3) and D3 is a known wart (different types,
    same semantics). Resolve when a real test forces the issue.
  - Aura kept separate from AddRule (Aura propagates unit-wide; AddRule grants
    to bearer only).
  - Heal is the only Effect with a DiceExpression amount; everything else
    uses plain int/float for fixed authored values.
  - IEntityRef marker interface dropped — token operations are split into
    Unit/Model variants for compile-time safety instead.

NOTES
-----

- Don't write the JSON/YAML loader until Phase 7 is done. Definitions are
  inline-constructed C# objects in tests until the model is proven.
- The engine refactor (042) is parallel work, not a prerequisite for Phases 1–6.
  Most rule tests assert that the right operation is queued, not that the
  operation actually executes against the engine.
- If you discover a missing helper while writing tests, add it to TestRuleHarness,
  not to the fixture file.
