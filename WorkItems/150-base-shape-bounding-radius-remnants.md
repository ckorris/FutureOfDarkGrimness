# 150 — Base-shape geometry: replace remaining bounding-radius approximations

**Status**: in-progress
**Related**: #149 (configurable base shapes — this is its deferred half), #050 (movement base-radius / swept-disc), #002 (zone shapes / SAT — `RotatedZoneWrapper` reusable for oriented rect geometry), #029 (Aircraft heading — refactored onto per-model facing here)
**Branch** (both repos): `150-base-shape-geometry`

## Goal
#149 makes **model-to-model** measurement shape-aware but, by decision, leaves the harder geometry approximating a non-circular base by its **bounding circle** (circumscribing radius). This item replaces those approximations with true shape geometry so a rectangular (or future) base collides/blocks/seizes with its real footprint, not a circle around it.

The bounding-circle remnants to address (catalogued during #149 — exact list finalized when #149 slice C lands):
- **Swept-path vs terrain** — `MovementUtilities.ValidateMovingThroughImpassibleTerrain` / `...DifficultTerrain` / `DoesPathCrossDangerousTerrain` and `PlacementUtilities.OverlapsImpassibleTerrain` inflate zones by the model's `BaseRadiusInches`. True geometry = Minkowski sum of the base shape with the zone along the path. Likely needs **base facing/rotation** to be meaningful for a rectangle.
- **Pile-in swept collision** — `PileInUtilities` (`MaxStepToTouch`, `LimitStepByObstructions`) uses combined radii for swept-disc model collision.
- **Move-through-enemy** — `MovementUtilities.ValidateMovingThroughEnemyUnits` / enemy footprints use radii.
- **Line of sight** — `LineOfSightUtilities.BuildModelBlockers` wraps each model in a `CircularZone(radius)`; a rectangular blocker should be a `RectangularZone`.
- **Objective seizure** — `ReconcileObjectivesStage` uses center-distance − `BaseRadiusInches` (model-to-objective base edge).
- **Base facing/rotation** — prerequisite for most of the above to be exact for rectangles; models have no facing today.

## Decisions
- **2026-07-01 — heading indicators + rotation→facing (user request).** (1) A small **heading triangle** at each model's front (its `Facing`) on the live table and the deploy/movement ghosts (`ModelBaseRenderer.DrawHeading*`). (2) The deploy/movement **rotation buttons** (wheel / R / Shift+R) now set facing: **group mode** faces the whole unit the rotated way; **single mode** rotates the selected model's facing in place (locking it). (3) **Movement default facing = direction of travel, per waypoint** — placing waypoints around a corner turns the model at each, shown live in the ghost; a hand-rotation overrides. Each waypoint carries its facing (parallel `ModelMoveEntry.Facings`) so presentation beats can lerp rotation. Deploy carries a single `PlacedObjectEntry.Facing`. Aircraft are excluded automatically (they don't use the GUI movement resolver). Engine `1d62433` (optional facing on both response records + apply-sites + `MovementFacingUtilities`); app in the paired superproject commit. Suite 965/0, headless exit 0. **GUI hand-verification pending.**

- **2026-06-30 — facing now, not deferred (with the user).** #150 will do oriented geometry, not just axis-aligned-exact. Prerequisite: a real per-model facing. The user clarified the representation: every model gets a **yaw-only rotation expressed as a 2D unit normal**; Aircraft must derive their heading from it (retiring the unit-level `AircraftHeading`).
- **2026-06-30 — facing is a store-backed `DataBinding<Float2>`** (mirrors `Position`): observable for rendering, network-replicated (a model turning syncs host→clients), and round-tripped by save/load. Default `(0,1)` = +Z, which reproduces the pre-#150 axis-aligned `RectangleBase` layout (width→X, height→Z), so existing armies/circles are unchanged. Cost: one appended `RegisterType<Float2>()` (type-map positional, so last). `IModel.Facing`/`SetFacing`/`OnFacingChanged`.
- **2026-06-30 — Aircraft heading lives on the models, gated by a token.** `UnitData.AircraftHeading` (nullable) is retired. `ForcedAircraftMove.EnsureHeading` aims toward table-centre on first move, writes it to every living model's `Facing`, and adds an `AircraftHeadingSet` token; once aimed it reads the heading back (asserting the models share one — an Aircraft never turns). Off-table clears the token to re-aim on redeploy. The token (not a nullable value) carries the "already aimed" tri-state, avoiding a default-vs-deliberate `(0,1)` ambiguity. Behaviorally identical to the old field.
- **2026-06-30 — no `AircraftHeading`-style unit fields going forward** (user: "I definitely don't like AircraftHeading"). Orientation is per-model; unit-level direction is a derived query over the models.

- **2026-07-02 — deploy stays on the table + per-axis packing for rectangles (user: "make sure it's not possible to deploy off the table, and that the AI won't try").** Engine `333dea6`, super `a007597`. Two things, found together while verifying with the rect/aircraft army:
  - **On-table guarantee.** Deployment zones sit flush with the table edge (`ChooseMapSideStage`: bottom `z∈[0,DEPLOY]`, top up to `TABLE_HEIGHT`, left/right to the edges), so a *footprint*-in-zone check is what keeps a base on the board. The GUI already did this; the CLI manual path and the AI only checked the base *centre* (`IsPointWithinZone`).   - **Per-axis packing (fixes a wide-rect cohesion crash the smoke surfaced).** A single spacing scalar can't pack a non-square base both overlap-free AND within the 1″ cohesion rule: the earlier circumscribed-radius choice over-spaced a 4×1.5 rectangle's short axis (rows 2.87″ apart → breaks nearest-neighbour), and the inscribed one overlapped the long axis. `BaseShapeGeometry.FootprintHalfExtents(shape, facing)` gives per-axis extents; `CohesiveFormation.PackGrid` (movement re-pack) and `AiPlaceObjectsResolver` (deploy) space columns by X and rows by Z (circle → the old square grid). CLI EOF fallbacks are now cohesive (full-zone rescan, then sit on a placed model), so headless auto-play never emits an out-of-cohesion deploy. `GroupFormationUtilities.ComputeDeploymentOffsets` is per-axis too. Test: `PackGrid_WideRectangles_ProduceCohesionValidFormation` (vs the real validator). Verified: engine 978/0, app 39/0, both builds clean, rect/aircraft-army headless runs to victory across repeated stochastic runs.
- **2026-07-02 — one facing-aware collision mechanism; all remaining disc-treatments migrated (user ask + everything-in-one-push).** Engine `2c4291c`, app in the paired superproject commit. The user reported rectangular colliders still behaving like circles and asked for a single, easy-to-call shape-vs-shape collision utility "not rewritten all over the place." Root cause (audited): the central `SurfaceGap2D` was **facing-blind** (rects measured axis-aligned) and a cluster of placement/movement-preview paths bypassed it for a scalar radius — worse, the *inscribed* one (so rectangles read too small and overlapped), with AI/CLI deploy on inscribed vs GUI deploy on circumscribed (three deploy paths disagreeing).
  - **Mechanism (retires #153):** each `IBaseShape` now yields a `BaseFootprint` (rounded convex hull — corners + Minkowski rounding) via `Footprint(centre, facing)`. `BaseShapeGeometry.SurfaceGap2D(a,posA,facingA,b,posB,facingB)` + `AreColliding(...)` consume only that through one hull-vs-hull routine (SAT overlap/penetration; nearest-feature separation). **No shape-pair switch** — a new shape implements one method. Circle-vs-circle stays byte-identical (two point hulls → `dist − rA − rB`). Facing-aware `DistanceUtilities` overloads; `IModel`/`ModelData` extensions thread facing, upgrading every `BaseDistanceToOtherModel` caller for free.
  - **Engine call-sites migrated:** the **mid-path move pass-through** (the #150 "4c" deferral) is now exact swept-shape-aware — *starts-clear + ends-clear + swept footprint crosses enemy ⇒ went through* (reuses the trusted `DoesSweptBaseIntersectZone`; the old disc `contactDistance`/`DistancePointToSegment2D` helpers deleted). `EnemyModelFootprint` carries facing. Melee range, shooting range, spell range, `ValidateCoherency`, pile-in coherency all facing-aware; `PileInUtilities.PathCrossesImpassable` no longer treats the mover as a point (swept footprint); `PlacementUtilities.OverlapsImpassibleTerrain` gained a shape+facing overload. Deploy/formation **layout** (AI placer, `CohesiveFormation`, `FDGServer` fallback row, AI consolidation table-edge) uses the **circumscribing** radius — a documented conservative bound that never overlaps/leaves-table for any facing, unifying the three deploy paths — while exact collision stays in the mechanism.
  - **App call-sites migrated:** GUI + CLI movement/consolidation resolvers — group + single overlap previews (`GroupPositionBlocked`, `WouldOverlapAnyModel`) use `AreColliding` with the phantom's live facing; `EnemyModelFootprint` construction carries shape+facing; cohesion + range/charge display measurements use the facing-aware overload (so previews match the server); coherency-repair layout + CLI/GUI deploy overlap use circumscribed radii; consolidation table-clamp circumscribed. Closes **3b** (placement-overlap + AI-movement scalar→shape).
