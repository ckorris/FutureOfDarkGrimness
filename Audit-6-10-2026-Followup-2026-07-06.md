# Follow-up Review: `Audit-6-10-2026.md` vs. Current State

**Date:** 2026-07-06
**Baseline:** `Audit-6-10-2026.md` (engine @ `099218d`, 326 tests, informal score 6.5/10)
**Now:** engine @ current `master`, **1138 engine tests** (+app suites), **366 commits** since the audit
**Method:** Cross-referenced every audit section/bug-log item against `WorkItemsList.md`'s "2026-06-10 audit follow-ups" ledger (which already tracks most of these by number), then spot-verified ~20 specific claims directly against source (grep/read), plus two parallel research passes covering networking/AI and tests/save-load/cleanup claims not otherwise tracked in the ledger. This is a diff report, not a re-audit from scratch — section scores from the original are not recomputed.

**Headline:** almost everything the audit flagged as high-value has been done, including the single item the audit called out as the biggest win in the whole codebase (the async-void stage-transition chain). The team's own work-item ledger turned out to be accurate everywhere it was checked. What's left open is mostly the lower-priority/deferred-by-design tail, plus a large amount of *new* surface area (Army Forge, per-model rules, base shapes, transport, casting) built since the audit that was never itself audited.

## 5. What's new since the audit (outside its original scope)

The audit was a snapshot of a ~36k-line engine; 366 commits later there's substantially more surface area that was never itself audited:

- **Army Forge builder** (#156) — a full catalog-driven army builder: 47 bundled OPR GDF books, upgrade options, combined units, item fidelity, rule-supplement import. This is a large new subsystem (its own parser/compiler pipeline, `FDG.ArmyBuilding`).
- **Per-model special rules** (#093) — per-model rule scope, movement budgets, activated abilities.
- **Base shapes & facing** (#149/#150/#153) — rectangular bases, per-model facing, unified shape-vs-shape collision geometry. Went through several rounds of real bugs (the #159 cohesion-crash saga is a good example of the kind of subtle geometry bug this class of change invites).
- **Transport** (#035/#096) — embark/disembark, spillout effects, visuals.
- **Casting/spells** (#033/#034) — token economy, spell targeting primitives, cast-assist.
- **Save/load rename fragility** (#070) — comprehensive fix, better than the audit's own recommendation scope (covers both the save fingerprint and the STJ rule-blob's `$type` payloads).
- **GUI/UX polish** — resolver consistency pass pending (#161, open), chat/log layout (#105, done), token display + health bars (#151/#152, done).

None of this is a criticism — it's a lot of shipped, tested functionality (suite went 326→1138 engine tests) — but it means a fresh, scoped audit of *these* subsystems (especially Army Forge's import/compile pipeline and the base-shape geometry, both large and both the kind of code where subtle bugs hide) would probably be more valuable now than re-auditing what's already been gone over once.
